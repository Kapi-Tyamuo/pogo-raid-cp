# レイド捕獲CP検索（Pokémon GO）

レイドで倒したポケモンの**捕獲画面CPの範囲**を、その場ですぐ引くための単体HTMLアプリ。

- `index.html` … これ1枚だけで動く。ネット接続不要。
- `artifact.html` … 同じ中身のArtifact公開用（`<html>`/`<head>` なし）。

## できること

| 機能 | 内容 |
| --- | --- |
| CP範囲 | 最大CP（15/15/15）と最低CP（レイドの個体値下限）、HP範囲 |
| モード切替 | 天候ブースト（Lv20 → Lv25）、シャドウレイド（個体値下限 10 → 6）。**一覧と詳細のどちらからでも切り替えられる** |
| 個体値の逆引き | 捕獲画面のCP（＋HP）を入力すると、ありうる個体値の組み合わせを列挙 |
| CP早見表 | Lv20 / Lv25 / Lv40 / Lv50 / Lv51（バディ最高ランク）のCP |
| おぼえる技 | 通常技・スペシャル技を威力／エネルギー／時間つきで一覧、レガシー技にバッジ |
| 検索 | 日本語名（ひらがな入力可）・英語名・図鑑番号。全1243種（リージョンフォーム含む） |
| 地方別の一覧 | 図鑑順にカントー〜パルデアの見出しを挟んで表示（見出しはスクロール中も固定） |
| 実装状況 | GO 未実装のポケモンにバッジを付け、まとめて隠せる |
| フォルム切替 | 同じ図鑑番号は一覧では1行にまとめ、詳細画面のタブで切り替える |
| タイプ表示 | 詳細画面にタイプ・分類・実装状況を表示。フォルムを切り替えると連動する |
| タイプ絞り込み | 18タイプから選んで一覧を絞る（複数選択はAND）。検索語とも併用できる |
| メガシンカ | メガ・ゲンシカイキ58種を詳細画面のタブで切り替え、種族値とタイプを表示 |

一覧は60件ずつ追記していく（表示件数の上限はなし）。下端まで来ると自動で足され、
スクロールイベントが届かない環境でも「残り N 件を表示」ボタンから続きを出せる。

表示範囲は「伝説・幻・UB（182件）」と「全ポケモン（1023件）」を切り替えられる。
選択と、天候ブースト／シャドウ／未実装を隠す の状態は localStorage に保存される。

### 絞り込み

「絞り込み」チップで開くパネルに、18タイプのボタンと「未実装を隠す」を入れている。
タイプを常に並べるとヘッダーが41px高くなるので開閉式にし、使用頻度の低い
「未実装を隠す」も同じパネルへ移して、閉じているときの高さを176pxに保っている。
チップには絞り込みの数（タイプ数＋未実装を隠す）が出る。

- タイプを複数選んだときは **AND**（選んだタイプを**すべて**持つポケモン）。
  ほのお＋ひこう → リザードン・ファイヤーなど6件。くさ＋どく → 14件。
  ポケモンは最大2タイプなので、3つ以上選べば必ず0件になる。
- **検索語と併用できる**。「りざーど」×ひこう → リザードンだけ、といった絞り方ができる。
- 表示範囲（伝説・幻・UB／全ポケモン）とも併用できる。
- タイプの選択は検索欄と同じ扱いで **localStorage に保存しない**。次に開いたとき
  「ほのおしか出ない」となるのを避けるため。天候ブーストなどの設定は従来どおり保存する。

絞り込みはフォルム単位で判定してからまとめるので、代表フォルムが条件に合わないときは
残ったフォルムが代表になる（タイプ「ドラゴン」ならナッシーはアローラのすがたで出る）。
このときは種の名前ではなくフォルム名で表示する。そうしないと名前とタイプが食い違う。

検索欄・天候ブースト／シャドウ・表示範囲の切替はすべて `<header>` にまとめて固定している。
スクロール中も条件を変えられるようにするため。固定部分は 375px 幅で176px。
地方の見出しはその実測値（`--headerH`）の下に張り付くので、チップが折り返して
高さが変わっても追随する（320px 幅では217px になる）。

地方の見出しは図鑑順に並ぶ**検索していないときだけ**出る。検索中は名前の先頭一致を
優先した順に並べ替わるので、地方の区切りが意味を持たなくなるため。

地方の判定には**図鑑番号の範囲**（`REGIONS`）を使う。元データの `generation` は
ヒスイの新種（アヤシシ〜ラブトロス No.899–905）を第9世代に入れており、そのまま使うと
パルデア地方に混ざってしまう。範囲は カントー 1–151 / ジョウト 152–251 /
ホウエン 252–386 / シンオウ 387–493 / イッシュ 494–649 / カロス 650–721 /
アローラ 722–809 / ガラル 810–898 / ヒスイ 899–905 / パルデア 906–1025。

ヒスイのすがた（ガーディなど）は元の種の図鑑番号のままなので、カントーなど元の地方に入る。
図鑑と同じ扱いで、フォルムは詳細画面のタブから見る。

No.902 イダイトウはゲームマスターに `pokemonSettings`（種族値・技）が無く、
サイズ設定しか入っていないため一覧に出ない。GO 側にデータが無いので、ヒスイは6件になる。

見出しはスクロール中もヘッダーの真下に固定され、次の地方に入ると押し上げられて
入れ替わる。これは地方ごとに入れ物（`.rgroup`）を作り、その中で `position: sticky`
させて実現している。平らに並べると全部の見出しが同じ位置に重なってしまう。
固定位置はヘッダーの実測値を `--headerH` として渡す（チップの折り返しで高さが変わるため、
描画時とリサイズ時に測り直す）。

詳細画面で条件を切り替えると、入力済みのCP/HPとスクロール位置は保たれる。
「CPが範囲外です」と言われて天候ブーストに切り替える、という流れのため。

### フォルムのまとめ方

アルセウス18種・ビビヨン20種・シルヴァディ18種などが一覧を埋めてしまうので、
**図鑑番号ごとに1行**にして、詳細画面のタブで切り替える（GO の図鑑と同じ考え方）。
1243エントリが1023行になる。

- 一覧に出す**代表フォルム**は、括弧なしの名前を優先し、次にリージョンフォームでないもの。
  ヒヒダルマは括弧なしが無いので「ノーマルモード」が代表になる。
- 一覧のCPは**代表フォルムの値**。デオキシス（1299–1806）やムゲンダイナ（2530–4678）の
  ようにフォルムでCPが変わるものは「N形態」バッジを出して詳細を見るよう促す。
  全フォルムを合わせた範囲は個体値の幅と混ざって誤読を招くので採らない。
- **検索したときは一致したフォルムをそのまま並べる**（「ガラル」で引けばガラルのすがた）。
  同じ図鑑番号は最初の一致だけ残す。
- タブには絞り込みで隠しているフォルムも並べ、未実装のものには注記を付ける。

タブの名前は括弧の中身を使うが、**アローラ・ガラルだけは元データが接頭辞で表す**
（「ガラル フリーザー」）ので、接頭辞も見て「ガラルのすがた」に直す。これをしないと
フリーザー・サンダー・ファイヤーのタブが両方「基本」になる（該当35グループ）。

括弧なしの基本フォルムは「基本」になるが、元データが
基本フォルムの呼び名を落としている一部は `NAME_OVERRIDE` で補っている（デオキシス→
ノーマルフォルム、アルセウス→ノーマルタイプ、シルヴァディ、ロトム、ポワルン、
ニャオニクス、パフュートンの7件）。ヒスイ・ガラル系は「基本」で意味が通るのでそのまま。

素の `ZACIAN` / `ZAMAZENTA` は `DROP_FORMS` で落としている。これは「れきせんのゆうしゃ」の
種族値・技に「けんのおう／たてのおう」のタイプが付いたテンプレート行で、ゲームには存在しない姿。
残すとタブが「基本」と「れきせんのゆうしゃ」に分かれ、しかもタイプが誤って はがね 付きになる。
落としたあとは `PREFERRED_FIRST` で「れきせんのゆうしゃ」を代表とタブの先頭に固定する
（レイドで捕まえるのはこの姿。放っておくと五十音順で「けんのおう」が先に来る）。

### メガシンカ・ゲンシカイキ

58種（メガ56・ゲンシ2）を、通常フォームと同じタブで切り替えられるようにしている。
ゲームマスターでは `pokemonSettings.tempEvoOverrides` に種族値とタイプが入っている。

- **一覧には出さない。** 捕まえられる姿ではないので、詳細画面のタブからだけ見る。
  代表フォルムにも選ばれない。名前検索でも引っかからない（「メガリザードン」では出ない）。
- **技は持たない。** GO ではメガシンカしても技は変わらないので、元の姿の技を借りている。
- 選択中はCPカードの見出しが「メガシンカ後」「ゲンシカイキ後」に変わり、
  **個体値の逆引きは出さない**（捕獲できないため）。
- タブ名は formId の末尾から決める（`_MEGA` → メガシンカ、`_MEGA_X` → メガシンカＸ、
  `_PRIMAL` → ゲンシカイキ）。名前が「メガリザードンＸ」のように括弧も接頭辞も持たないため。

**メガの実装状況は判定していない。** 使えそうな材料は `temporaryEvolutionSettings` の
`assetBundleValue` だけだが、ゲームマスターが 2026-04 で止まっているため、それ以降に
実装されたメガ（メガミュウツーX/Y、メガライチュウX/Y、メガスターミー、メガエアームド、
メガタイレーツ）を未実装と誤判定してしまう。Z-A のメガでも早期に来たメガカイリュー・
メガウツボット・メガカラマネロは正しく判定できるので、単に情報が古いだけ。
誤ったバッジを出すより出さない方がましなので、メガは一律で実装済み扱いにしている。
（通常フォームの判定に使う `pokemonSettings.modelScaleV2` は有効。`tempEvoOverrides` の
`modelScaleV2` は基準と違う拡大率のときだけ付くので、メガには使えない。）

### 「未実装」の判定

**ゲームマスターの `pokemonSettings` に3Dモデルの設定（`modelScaleV2`）があるか**で判定している。
Niantic は未実装ポケモンの種族値も先行して配信しているが、モデル設定は実際にゲームへ
入るまで付かない。既知の実装済み13種（ミミッキュ・アルセウス・マギアナ・メタモン等）で
誤判定ゼロを確認済み。現在の判定結果は未実装52件で、すべてパルデア地方。

採用しなかったデータ源:

- `pogoapi.net/api/v1/released_pokemon.json` … 古く、ミミッキュ・ゼラオラ・アルセウス・
  マナフィなどを未実装としてしまう
- pvpoke の `released` … 「PvPランキングの対象か」の意味で、メタモンやヌケニンが `false`
- 画像アセットの有無 … フォーム名付きのファイル名になっており、実装済みでも欠けることがある

ニドラン♀♂は formId が共通（`NIDORAN`）でゲームマスター側は種ID基準なので、
formId で引けないときは種IDでも引く。この副作用でウッウの「まるのみ／うのみのすがた」は
種として実装済みのため実装済み扱いになる。

### フォームの扱い

元データ（1399件）には、CPを引くうえで区別できない行がかなり混ざっているので `fetch_data.py` で整理している。

- **CPが同じフォームを統合（103件）** — `RAIKOU` / `RAIKOU_S`、アンノーンのA〜Z、メテノの色違いなど。名前・図鑑番号・種族値・タイプがすべて同じものは1件にまとめ、技が最も多く登録されている行を代表にする。
- **テンプレート行を削除（51件）** — `DARMANITAN`（素）と `DARMANITAN_STANDARD`（ノーマルモード）のような重複。種族値・タイプが一致し、かつ技が既定フォーム側にすべて含まれるときだけ素の方を捨てる（メロエッタ・ゲノセクト・ニャオニクスのように技が違う場合は両方残す）。
- **日本語フォーム名の補完** — ヒスイ・パルデアなど、元データが素の名前のままにしているフォームに `FORM_LABEL` で名前を付ける。未登録の接尾辞が出たらビルド時に警告が出る。

## 計算式

```
CP = ⌊ (攻撃+個体値) × √(防御+個体値) × √(HP+個体値) × CPM² ÷ 10 ⌋   （最低10）
HP = ⌊ (HP種族値+個体値) × CPM ⌋                                   （最低10）
```

CPM は `game_master` の `playerLevel.cpMultiplier`（Lv20 = 0.5974、Lv25 = 0.667934）。

ミュウツー 2294–2387 / ブースト 2868–2984、レックウザ 2102–2191、カイオーガ 2260–2351、
最大強化CP（ミュウツー 4724 / レックウザ 4336 / カイオーガ 4652）がゲーム内の値と一致することを確認済み。

## スマホで使う

### GitHub Pages（PWA）

`docs/` が Service Worker つきの PWA になっている。GitHub Pages で公開してから、

1. iPhone の Safari で公開URLを開く
2. 共有ボタン →「ホーム画面に追加」

初回だけ通信して端末にキャッシュするので、以降は**圏外でもアイコンから起動できる**。

公開設定は リポジトリの Settings → Pages → Source: `Deploy from a branch` → `main` / `/docs`。

ビルドし直すと `sw.js` のキャッシュ名（配信する `docs/index.html` のSHA-256の先頭12桁）が変わる。
新しい Service Worker が有効になった時点でページ側が `controllerchange` を拾って読み直すので、
**開いたその場で新しい版に切り替わる**（この処理がないと、次に開くまで古いキャッシュが表示される）。

### 引っぱって更新

ホーム画面から起動した PWA には Safari の更新機能が無く、キャッシュ優先で動くので、
アプリを起動し直さないと新しい版に気づけない。自前の pull-to-refresh を用意している。

上端で下に70px引っぱって離すと `registration.update()` を呼ぶ。新しい版があれば
`reg.installing` / `reg.waiting` が立つので「新しい版を取得中…」に切り替え、有効化されると
`controllerchange` で読み直される。無ければ「最新です」、圏外なら「オフラインです」。

- 引っぱっている間は**中身ごと押し下げる**。ピルだけ動かすと検索欄に重なって読めなくなる。
- `touchmove` で `preventDefault()` して iOS のバウンドを止め、自前の表示に置き換えている。
- 横方向の移動が縦より大きいときは反応しない（フォルムのタブを横スクロールできるように）。
- 一覧と詳細画面のどちらでも効く。スクロール位置が上端のときだけ。
- タッチ環境の判定（`ontouchstart`）は端末によって当てにならないので条件を付けていない。
  タッチが無ければイベントが発火しないだけ。

### ファイルを直接渡す

`index.html` は外部ファイルを一切参照しない1枚もの。AirDrop でiPhoneに送って
ファイルアプリから開けば、公開せずにオフラインで使える（ホーム画面アイコンは作れない）。

## データの更新

新しいポケモンや技が追加されたら:

```bash
python3 fetch_data.py   # 公開データを取得して src/godata.json を再生成
python3 build.py        # index.html / artifact.html を再ビルド
```

`--cache` を付けると `.cache/` の既存ダウンロードを使い回す。

### 出典

- 種族値・技・多言語名・世代: [pokemon-go-api](https://pokemon-go-api.github.io/pokemon-go-api/)

## ファイル構成

```
pogo-raid-cp/
├── index.html        # 生成物：単体HTML（AirDrop 用）
├── artifact.html     # 生成物：Artifact 公開用
├── docs/             # 生成物：GitHub Pages 用の PWA 一式
│   ├── index.html
│   ├── manifest.webmanifest
│   ├── sw.js         # キャッシュ名にページ内容のハッシュが入る
│   └── icon-*.png    # src/*.svg から sips で生成
├── build.py          # src/body.html + データ → 上記すべて
├── fetch_data.py     # 公開データ → src/godata.json
├── src/
│   ├── body.html     # アプリ本体（HTML/CSS/JS）。__DATA__ にデータが差し込まれる
│   ├── icon.svg      # ホーム画面アイコン
│   ├── icon-maskable.svg
│   └── godata.json   # 生成物（144KB）
└── .cache/           # ダウンロード済みの元データ（gitignore 対象）
```

`docs/` は生成物だが、GitHub Pages が参照するのでコミットする。
