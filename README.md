# レイド捕獲CP検索（Pokémon GO）

レイドで倒したポケモンの**捕獲画面CPの範囲**を、その場ですぐ引くための単体HTMLアプリ。

- `index.html` … これ1枚だけで動く。ネット接続不要。
- `artifact.html` … 同じ中身のArtifact公開用（`<html>`/`<head>` なし）。

## できること

| 機能 | 内容 |
| --- | --- |
| CP範囲 | 最大CP（15/15/15）と最低CP（レイドの個体値下限）、HP範囲 |
| モード切替 | 天候ブースト（Lv20 → Lv25）、シャドウレイド（個体値下限 10 → 6）。**一覧と詳細のどちらからでも切り替えられる** |
| 個体値の逆引き | 捕獲画面のCP（＋HP）を入力すると、ありうる個体値の組み合わせを列挙 |
| CP早見表 | Lv20 / Lv25 / Lv40 / Lv50 / Lv51（バディ最高ランク）のCP |
| おぼえる技 | 通常技・スペシャル技を威力／エネルギー／時間つきで一覧、レガシー技にバッジ |
| 検索 | 日本語名（ひらがな入力可）・英語名・図鑑番号。全1245種（リージョンフォーム含む） |
| 地方別の一覧 | 図鑑順にカントー〜パルデアの見出しを挟んで表示 |
| 実装状況 | GO 未実装のポケモンにバッジを付け、まとめて隠せる |

一覧は60件ずつ追記していく（表示件数の上限はなし）。下端まで来ると自動で足され、
スクロールイベントが届かない環境でも「残り N 件を表示」ボタンから続きを出せる。

表示範囲は「伝説・幻・UB（182件）」と「全ポケモン（1245件）」を切り替えられる。
選択と、天候ブースト／シャドウ／未実装を隠す の状態は localStorage に保存される。

地方の見出しは図鑑順に並ぶ**検索していないときだけ**出る。検索中は名前の先頭一致を
優先した順に並べ替わるので、地方の区切りが意味を持たなくなるため。

詳細画面で条件を切り替えると、入力済みのCP/HPとスクロール位置は保たれる。
「CPが範囲外です」と言われて天候ブーストに切り替える、という流れのため。

### 「未実装」の判定

**ゲームマスターの `pokemonSettings` に3Dモデルの設定（`modelScaleV2`）があるか**で判定している。
Niantic は未実装ポケモンの種族値も先行して配信しているが、モデル設定は実際にゲームへ
入るまで付かない。既知の実装済み13種（ミミッキュ・アルセウス・マギアナ・メタモン等）で
誤判定ゼロを確認済み。現在の判定結果は未実装52件で、すべてパルデア地方。

採用しなかったデータ源:

- `pogoapi.net/api/v1/released_pokemon.json` … 古く、ミミッキュ・ゼラオラ・アルセウス・
  マナフィなどを未実装としてしまう
- pvpoke の `released` … 「PvPランキングの対象か」の意味で、メタモンやヌケニンが `false`
- 画像アセットの有無 … フォーム名付きのファイル名になっており、実装済みでも欠けることがある

ニドラン♀♂は formId が共通（`NIDORAN`）でゲームマスター側は種ID基準なので、
formId で引けないときは種IDでも引く。この副作用でウッウの「まるのみ／うのみのすがた」は
種として実装済みのため実装済み扱いになる。

### フォームの扱い

元データ（1399件）には、CPを引くうえで区別できない行がかなり混ざっているので `fetch_data.py` で整理している。

- **CPが同じフォームを統合（103件）** — `RAIKOU` / `RAIKOU_S`、アンノーンのA〜Z、メテノの色違いなど。名前・図鑑番号・種族値・タイプがすべて同じものは1件にまとめ、技が最も多く登録されている行を代表にする。
- **テンプレート行を削除（51件）** — `DARMANITAN`（素）と `DARMANITAN_STANDARD`（ノーマルモード）のような重複。種族値・タイプが一致し、かつ技が既定フォーム側にすべて含まれるときだけ素の方を捨てる（メロエッタ・ゲノセクト・ニャオニクスのように技が違う場合は両方残す）。
- **日本語フォーム名の補完** — ヒスイ・パルデアなど、元データが素の名前のままにしているフォームに `FORM_LABEL` で名前を付ける。未登録の接尾辞が出たらビルド時に警告が出る。

## 計算式

```
CP = ⌊ (攻撃+個体値) × √(防御+個体値) × √(HP+個体値) × CPM² ÷ 10 ⌋   （最低10）
HP = ⌊ (HP種族値+個体値) × CPM ⌋                                   （最低10）
```

CPM は `game_master` の `playerLevel.cpMultiplier`（Lv20 = 0.5974、Lv25 = 0.667934）。

ミュウツー 2294–2387 / ブースト 2868–2984、レックウザ 2102–2191、カイオーガ 2260–2351、
最大強化CP（ミュウツー 4724 / レックウザ 4336 / カイオーガ 4652）がゲーム内の値と一致することを確認済み。

## スマホで使う

### GitHub Pages（PWA）

`docs/` が Service Worker つきの PWA になっている。GitHub Pages で公開してから、

1. iPhone の Safari で公開URLを開く
2. 共有ボタン →「ホーム画面に追加」

初回だけ通信して端末にキャッシュするので、以降は**圏外でもアイコンから起動できる**。

公開設定は リポジトリの Settings → Pages → Source: `Deploy from a branch` → `main` / `/docs`。

ビルドし直すと `sw.js` のキャッシュ名（配信する `docs/index.html` のSHA-256の先頭12桁）が変わる。
新しい Service Worker が有効になった時点でページ側が `controllerchange` を拾って読み直すので、
**開いたその場で新しい版に切り替わる**（この処理がないと、次に開くまで古いキャッシュが表示される）。

### ファイルを直接渡す

`index.html` は外部ファイルを一切参照しない1枚もの。AirDrop でiPhoneに送って
ファイルアプリから開けば、公開せずにオフラインで使える（ホーム画面アイコンは作れない）。

## データの更新

新しいポケモンや技が追加されたら:

```bash
python3 fetch_data.py   # 公開データを取得して src/godata.json を再生成
python3 build.py        # index.html / artifact.html を再ビルド
```

`--cache` を付けると `.cache/` の既存ダウンロードを使い回す。

## ファイル構成

```
pogo-raid-cp/
├── index.html        # 生成物：単体HTML（AirDrop 用）
├── artifact.html     # 生成物：Artifact 公開用
├── docs/             # 生成物：GitHub Pages 用の PWA 一式
│   ├── index.html
│   ├── manifest.webmanifest
│   ├── sw.js         # キャッシュ名にページ内容のハッシュが入る
│   └── icon-*.png    # src/*.svg から sips で生成
├── build.py          # src/body.html + データ → 上記すべて
├── fetch_data.py     # 公開データ → src/godata.json
├── src/
│   ├── body.html     # アプリ本体（HTML/CSS/JS）。__DATA__ にデータが差し込まれる
│   ├── icon.svg      # ホーム画面アイコン
│   ├── icon-maskable.svg
│   └── godata.json   # 生成物（144KB）
└── .cache/           # ダウンロード済みの元データ（gitignore 対象）
```

`docs/` は生成物だが、GitHub Pages が参照するのでコミットする。
